# Skill 精简与重构

把臃肿、跳跃或过期的 Agent Skill 改得紧凑顺畅：让 Agent 用更少的上下文、顺着单一路径读懂规矩，同时一处不丢真正管住产出的硬性约束。

| 文件 | 何时读 / 何时跑 |
|---|---|
| `scripts/skill_check.py` | 动笔前跑一次拿基线，改完再跑一次验链接、锚点、孤立文件、字数与句式密度 |
| [references/pipeline-and-gates.md](references/pipeline-and-gates.md) | 目标是多技能套件、带校验/门禁脚本，或会向子 Agent 派发任务时读 |

按下面六步顺序执行，不要跳步。

---

## 第一步：摸底基线与真实事实核对

1. **跑静态基线**：对目标技能目录运行 `python3 <本技能目录>/scripts/skill_check.py <目标路径>`，记录文件数、`SKILL.md` 行数、**非空白总字数**、断链/失效锚点、孤立文件和跨节跳转次数。衡量上下文开销以非空白字数为准，不能只看行数——把短句拼成超长单行段落会让行数表面下降、实际字数反而暴涨。
2. **对照代码与线上现状核实事实**：只要技能涉及真实产品、CLI 脚本、环境变量、配额或接口行为，动笔前必须去源码、`--help`、配置常量或真实页面逐项核对，把已下线入口、旧参数、错配额和失效说明同步订正，绝不凭印象润色过期规则。

---

## 第二步：重排阅读动线与文件分工

先治结构病，再改字句。结构乱的根源通常是把同一件事拆散在七八个角落，逼着读者和模型前后翻找。

1. **按认知与执行先后排成单向直线**：
   - 读者或 Agent 在某一步需要先懂什么概念、看哪张总表，就在那一步之前交代清楚；禁止先抛缩写、代号或分类统计，隔几节才解释背景与来源。
   - **彻底拆掉重复板块**：一份文档里不要并排摆两个概览（如既有结论摘要又有一页速览），不要把同一批待定事项拆成「外部确认」「补充过渡口径」「内部未决」三节重抄，也不要首尾各列一张文件清单。**同一条规则、同一张清单全技能只保留一处正文**，其他位置最多用一句话指路。
   - 消灭正文里的 `见第 X 节`、`详见下文` 乒乓跳转；需要凑在一起才能做决定的规则，直接合并到同一节。

2. **`SKILL.md` 与 `references/` 按需分层**：
   - **`SKILL.md` 自足承载主干**（硬上限 500 行，常规单技能控制在 300 行以内）：写清适用边界、参考文件触发条件、主干步骤、**前置的精确输出结构（标题层级、表格列名、JSON 字段）**与核心禁令，让常规任务不必翻遍所有附件也能跑通。
   - **内联必读短文，合并碎片微文件**：每次运行都绕不开的几十行短文件直接并回 `SKILL.md`。若完成一个动作需要连开五六个三四十行的微参考文件，按业务阶段或主题合并成内聚指南，减少工具读取轮次。
   - **只留顶部条件路由表**：在 `SKILL.md` 开头用一张表写清每个附件在什么条件下才打开；正文中已按条件链接过的附件，删掉文末重复罗列的参考资料索引。

3. **严守单技能自包含边界**：
   - 每个 `skills/<slug>/` 都可能被单独安装或打包分发。所有相对链接必须落在本技能目录内且标题锚点真实存在，严禁写 `../other-skill/...` 跨目录路径；跨技能衔接直接写目标技能名（如 `$prose-gap-polish`）。
   - YAML frontmatter 的 `name` 必须与目录名一致，`description` 必须写在同一行（不超过 1024 字符，写明核心职责与中英文触发词，禁用 `|` 或 `>` 多行块标量，避免部分 Agent 工具解析器截断报错）。

---

## 第三步：果断砍掉六类低信号噪音

凡是不改变 Agent 具体动作、判断标准或输出格式的文字，一律删净：

1. **空泛导语与面向人类的培训说教**：口号式引言、职业心态劝导、给人类看的商业案例书单，或解释「为什么要重视质量」的铺垫。
2. **文末复读式自查清单**：把正文各步已经讲透的要求在末尾换个勾选项重抄一遍的清单，整段删掉；末尾只保留正文未展开、仅在交付前核对的独立检查项。
3. **研发实验流水账**：把「我们试了 8 次发现模型有 5 次会漏掉……」压成一句直接指令与正反例，踩坑过程留给提交说明或维护笔记。
4. **脚本内部实现旁白与括号堆砌**：锁机制、哈希算法细节、已废弃旧字段的兼容历史，以及正文里连串叠放的括号说明（如字节上限、固定列数、手改会被校验脚本拦下）——只要不需要读者当场配合操作，全部从概述与正文移除，只留准确的调用命令、参数与退出码分支；确属硬约束的规格单独留在对应规则小节。
5. **无真实触发场景的预留分支与空转仪式**：删掉从未启用的配置项；方向已经明确时，取消硬凑多套假设方案或分两轮空跑的繁琐流程。
6. **同义反复叮嘱**：同一禁令在概览、步骤、注意事项里换三种说法反复强调，只留位置最准的一处。

**精简对照示例**：

- ❌ **改前**（实验流水账 + 培训说教 + 重复叮嘱）：
  > 为什么要严格限制情绪形容词？在前期测试的 12 篇样稿里，我们发现模型一旦偷懒直接写“他很愤怒”，人物就会显得扁平，缺乏画面感（这是新手最常犯的通病）。因此，请务必建立视觉化写作意识，绝对不要只写抽象情绪词，而是一定要用动作来体现。注意：切记不要直接写抽象情绪！
- ✅ **改后**（直接给规则 + 防跑偏边界）：
  > 情绪表达四选一，地位平等：直白情绪词（任何强度均可）、利害盘算或吐槽、对话选择、能改变局面的动作或物件反应。禁止为了回避情绪词硬塞摩挲杯沿、按住桌角等无意义微动作。

## 第四步：清理直译黑话、机械句式与模板污染

1. **把英文直译、生造概念与不地道的外来行话改成自然行业中文**：
   - 替换生硬译腔与自造工程词：`唯一事实源 / 唯一底账 / 结构化权威` → 直接写清数据统一记在哪个文件里（或「主数据文件」）；`衍生文件 / 派生视图 / 投影` → `自动生成的表格 / 直接展示`；`落盘` → `保存到文件 / 写入本地`；`静默错读 / 静默忽略` → `不作提示直接读取 / 忽略参数继续运行`；`回查真值` → `核对真实数据`；`宿主机 / Agent 宿主` → `本机 / Agent 工具`；`赋能 / 抓手 / 心智模型 / 认知闭环 / 同一个创作大脑` → 直接写谁在什么条件下做什么动作。
   - 中文网文、短剧、影视与游戏创作文档里，把洋泾浜或生硬套用的英文写作课黑话（如 `POV 代价`、`tell 多于 show`）改成本行业创作者真正使用的地道说法（如「单视角局限」「转折缺铺垫、靠大段心理独白硬讲」）。
   - 保留业内通行且表意更准的标准技术术语（如 `SHA-256`、`AST`、`OTP`、`LUFS`、`ASR`），不强行生造中文词。

2. **清理公式体、伪代码与机械对比句**：
   - 正文说明不用 `A = B -> C` 箭头公式或竖线拼接串（如 `入点|出点|钩子理由`）代替自然中文。
   - 消除泛滥的 `不是 A，而是 B` 机械对比句式（改用 `只做 B，不做 A` 或直接陈述做法）。
   - 不拿弯引号 `“…”` 当普通词汇的强调符号；正文弯引号密度控制在每千字 3 对以内（界面按钮、文档与章节名优先用 `「…」` 或反引号）。

3. **清除模板与内联示例污染**：
   - **模板去具体业务 ID 与死板填空**：示例或骨架模板里不预填具体业务编号（如 `["DEV-01"]`，模型在无关场景会原样照抄造成悬空引用），也不写诱导机械填空的 `[在此填写压力表现]`；改用空数组或带语义说明的尖括号占位符（如 `<可复制提示词正文，语言服从项目设定；未指定时默认中文>`）。
   - **内联示例必须逻辑自洽、可落地**：删掉缺前因后果的半截示例，或画面生成提示词里无法拍摄的心理描写（如 `仿佛看透了命运`），换成筹码具体、前后咬合的真实写法。

---

## 第五步：逐段对照基线回查，守住六类操作约束

大幅精简最容易误删管用规矩，或在合句时无意收窄适用范围。改完初稿后，必须逐段阅读 `git diff` 对照原版回查；凡误伤以下六类内容，立即恢复：

1. **时序隔离与读取条件**：例如盲测类技能「首轮体验结束前严禁读产品事实表」的先后禁令。
2. **前置的精确输出格式**：下游脚本、解析器或交接方依赖的标题字面文本、表格列名、状态标签枚举和文件路径。
3. **成对的正反对照例（`❌ / ✅`）**：一组好坏分明的实例胜过三段抽象原则，精简时优先砍原则解释、保留对照实例。
4. **交付节点的独立复核与保密红线**：哪些信息能进可转发文档、哪些只能留在当前对话，以及多视角独立挑错的要求。
5. **防矫枉过正的平衡边界**：禁掉一种套路写法时，是否保留了同等地位的自然替代路径；合并多分支规则时，核对有没有把「A 或 B 皆可」误缩成「只能 A」。
6. **无状态环境与子 Agent 的字面指令**：每次工具调用不共享 shell 变量时的字面路径写法、独立浏览器会话参数、精确退出码处理，以及发给子 Agent 的完整输出表头（禁止写 `格式同上表` 让子 Agent 跨段猜结构）。

---

## 第六步：机械校验与收尾核验

1. 重新运行 `python3 <本技能目录>/scripts/skill_check.py <目标路径>`，确认返回 `PASS`：零断链、零失效锚点、零跨目录路径越界、零孤立文件、零本机个人路径残留，且跨节跳转与机械对比句已清零或降至合理范围。
2. 若目标仓库配有单测、文档字数预算或分发打包校验（如 `unittest`、`validate_repo.py`、`clawhub_release.py validate`），全部跑通；只要技能目录内有内容改动，即同步递增分发清单中的版本号并刷新摘要（如 `.clawhub/publish.json` 与 `clawhub_release.py lock`）；涉及文件增删或改名时，一并更新仓库 README、`clawhub-sources.json` 及安装清理配置。
