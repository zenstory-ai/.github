# 多技能套件、门禁脚本与子 Agent 派发优化指南

当优化对象包含多个协作技能、`scripts/` 校验门禁或子 Agent 任务派发时，除主流程六步外，按以下准则收敛边界与门禁。

---

## 1. 多技能合并与拆分判据

把一个完整工作流拆成过多细碎技能，会导致路由误判、公共脚本重复拷贝、单包安装缺依赖；全塞进一个巨型技能又会撑爆单次上下文。按以下三条判据决定合与分：

1. **共享上下文与中间产物紧耦合的连续阶段 → 合并为单入口多阶段技能**：
   - 若多个技能按固定先后顺序串联、共享同一套配置与目录结构，且单独装其中一个几乎无法独立完成交付（如把同一条制作链路拆成理解、写稿、粗剪、配音、合成五个独立技能），应合并为一个主技能，内部按阶段按需加载对应 `references/`，共用一套底层工具库。
   - 若相邻阶段在需求边界上高度重叠（如概念定位、世界观规则、美术方向都需要先锁定目标完成度与核心体验），合并为同一技能内的递进步骤，消除交接折损。
2. **可独立复用的旁路工具 → 保留独立技能**：
   - 不参与主生产链路、单独调用就能产出明确结果的工具（如独立的样片拆解入库、独立的文案精修、独立的发布说明核验），保持独立技能目录，不与主链路硬绑。
3. **跨技能产物只认单一底账**：
   - 上游技能已产出的完整结构化清单（如全量节点表、分章索引），下游报告或汇总文档只写一句话指针与关键结论摘要，禁止把几百字原文引用再抄一遍，防止续跑或返修时两份文件不一致。

---

## 2. 脚本与 Agent 的职责切分及门禁校准

遵循**脚本管客观底线与手脚，Agent 管语义判断与审美**的分工，清理越界脚本与误伤门禁：

1. **脚本必须兜住的客观硬指标（硬阻断 `error`）**：
   - 文件是否存在、JSON/YAML 语法与必填字段、跨文件 ID 引用完整性、时长/字数硬上下限、音画轨缺失或截断、哈希锁一致性、链接与锚点有效性、敏感凭据或本机路径泄露。
   - 技能自带脚本优先使用 Python 3.9+ 标准库编写，所有文本读写显式指定 `encoding="utf-8"`，不依赖外部私有包，也不跨目录 `import` 兄弟技能脚本。
2. **必须从脚本移交回 Agent（或降级为非阻断提示 `warning`）的判断**：
   - 需要结合上下文才能定性的审美与叙事选择（如某一段是否适合静态镜头、某句反问是否契合人物关系、某条改写意见是否值得采纳），禁止用简陋关键词表或打分公式一刀切拦截。
   - **校准单次命中误伤**：正常中文表达里偶发一次的句式、省略号或对话破折号，单次命中就硬拦截会造成大面积误伤并逼出僵硬改写。应改为按篇幅折算的**密集度拦截 + 低频提示**（如有真实人类样本库，先跑回测把正常作品误拦率压到极低水平再开硬阻断）。
   - **消除改动连坐**：校验与生产状态锁应按条目或段落计算摘要（如单镜头、单章节哈希），改一处错字不应导致整集或全书已确认的产物全部失效重跑。
3. **防范规则诱发的矫枉过正**：
   - 当某条生成规则严禁一类写法、校验脚本又提示「请改成具体动作/细节」时，模型极易走向另一个极端（例如为躲避情绪词，满篇堆砌摩挲手指、垂眸停顿等慢动作）。定规则时必须同时给出多条地位平等的自然表达通道，并把高频替代套路本身纳入巡检。

## 3. 子 Agent 派发与运行环境适配

1. **派发包自包含，禁用跨段指代**：
   - 派发给子 Agent（尤其是轻量模型）的任务说明必须自带完整的输入边界、字面输出表头或 JSON 示例，禁止写 `字段同上表`、`按第三节格式输出`。
   - 子 Agent 若运行在受限目录或独立沙箱中，提示词里引用的所有参考文件必须落在该子 Agent 实际可读的目录范围内，并用静态检查验证路径存在。
2. **先探测工具能力，不私自偷换交付物**：
   - 涉及外部命令行、浏览器自动化、媒体渲染或 MCP 服务时，开跑先做一次轻量连通性探测（已配置不代表当前可达）。
   - 若目标运行环境、模型配额或登录条件不可用，或遇到验证码/人机校验拦截，立即停在边界内如实记录未覆盖范围与原因；严禁绕过限制，也严禁在未获确认时把约定的桌面端/成片交付擅自降级成网页草稿冒充完成。
