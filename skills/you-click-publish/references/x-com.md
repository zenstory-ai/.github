# x.com

## 文章（Articles）

- 标题用定稿标题；副标题可选，长文通常不需要。
- 正文段落之间**不留空行**，粘贴到 X 文章编辑器后空行会破坏格式。
- 少用 Markdown：X 文章编辑器不渲染 `##`、`**`，需要小标题时用编辑器自带的样式，或用「一、」「二、」开头的普通段落。
- 链接写完整的 `https://` 地址，单独一行。

## 配套推文

文章发布时可以附一条推文引流，三到五行：一句痛点、一句做了什么、两个要点、链接。

**字数算法**：上限 280。中日韩字符和全角符号每个算 2，其他字符算 1，链接无论多长都算 23。用脚本检查：

```bash
python3 scripts/x_weight.py tweet.txt
```

## 头图

X 文章头图建议 **5:2**，做成 2000×800 的 PNG。

1. **画面交给图像模型**（例如 Codex 的 imagegen）。提示词里写清：构图（主体放哪一侧）、留白区域（给文字留出左下角之类的空位）、只渲染短英文标题、不要其他文字和水印。生成后裁成 5:2。
2. **中文用 HTML 叠加**。图像模型写中文容易错字，把副标题、名称这类中文放进一个 HTML 页面，背景是生成的图，用无头 Chrome 截图：

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
  --hide-scrollbars --force-device-scale-factor=1 --window-size=2000,800 \
  --screenshot="$PWD/header.png" "file://$PWD/header.html"
```

3. 截图后自己看一遍：文字有没有压住主体、元素是否完整、尺寸是否 2000×800。

图像模型调用失败时（例如默认模型对当前账号不可用），单次指定一个账号可用的模型重试，不要改人的全局配置；并告诉人这件事。

## 在浏览器里填草稿

与 linux.do 相同的原则：在人已登录的浏览器里，打开新建文章 → 填标题 → 粘贴正文 → 上传头图 → 截图核对 → 停在发布按钮前。推文同理，填好不发。
