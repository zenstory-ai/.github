# 你来点发布

Agent 能把发帖里最费时间的部分做完：按平台改写、配图、算字数、在编辑器里填好标题正文分类标签。
但**写什么、怎么说、发不发，都是人的事**。本 skill 的每一步都给人留出修改的位置，最后停在发布按钮前。

参考文件：

| 文件 | 何时读 |
|---|---|
| [references/writing.md](references/writing.md) | 起草和改稿前：语气、句式、真实性的规则，以及已经踩过的坑 |
| [references/x-com.md](references/x-com.md) | 发 X 文章和推文时：格式、字数算法、头图做法 |
| [references/linux-do.md](references/linux-do.md) | 发 linux.do 时：开源推广声明、排版、在编辑器里填草稿的步骤 |
| [scripts/x_weight.py](scripts/x_weight.py) | 检查推文是否在 280 的上限内 |

## 1. 三条底线

1. **不替人发布。** 不点「发布 / 创建话题 / Post」，不调用任何会直接发出内容的接口。草稿填好后截图给人看，由人点。
2. **不替人做承诺，不编经历。** 平台要求的声明（例如 linux.do 开源推广里「AI 生成内容已截图发出」）由人决定怎么勾；正文里的亲身感受、数据、成果只写真实发生过的，拿不准就标出来问人。
3. **不绕过平台的人机验证和风控。** 遇到 Cloudflare 验证、登录、二次确认，停下来请人自己操作。不用超长网址、批量请求这类容易触发风控的做法。

## 2. 流程

1. **定素材和口径**：这篇要推广什么（链接、名字、一句话价值），真实的起因是什么，有哪些不能公开的细节。保密内容在第一稿就换成虚构示例或泛化说法。
2. **起草**：先写一版完整正文，按 [references/writing.md](references/writing.md) 的规则。标题给 3–4 个方向，说明各自的取舍，推荐一个。
3. **人改稿**：把稿子写进文件（例如 `<名字>-x.txt`、`<名字>-linuxdo.md`）交给人。人改过的版本就是定稿，**之后只调格式，不再改内容**；人在对话里贴回的修改，逐条照做。
4. **按平台适配**：X 见 [references/x-com.md](references/x-com.md)，linux.do 见 [references/linux-do.md](references/linux-do.md)。同一篇内容在两个平台的语气、排版、配图要求不同，不要一稿通发。
5. **配图（需要时）**：X 文章头图 5:2。画面交给图像模型，**中文文字用 HTML 叠加渲染**，保证一字不差。
6. **填草稿**：在人自己已登录的浏览器里一步步填（见各平台文件）。每填完一项就核对：标题、正文逐字等于定稿文件，预览已渲染，分类标签正确。
7. **交给人发布**：截图展示草稿状态，说明还需要人做什么（关掉提示浮层、最后看一眼预览、点发布）。人发布后，按需清理临时启动的浏览器。

## 3. 浏览器怎么用

- 优先使用人自己的浏览器和登录态。可用的方式按顺序：宿主自带的人机协作浏览器；Claude in Chrome 扩展；通过 CDP 连接人的 Chrome（需要时安装 `browser-cdp` 这类 skill，启动前必须问人，因为会重启 Chrome）。
- 一个工具连续两三次失败就换方式或问人，不要反复重试同一个动作。
- 操作像人：打开页面 → 点「新建」→ 输入标题 → 粘贴正文 → 选分类标签。正文用一次性粘贴（设置输入框的值），不要逐字敲：编辑器的列表自动续写会把 `* ` 之类的格式弄乱。
- 不在地址栏里塞整篇正文去预填编辑器，链接过长会被风控拦截。

## 4. 自查清单

- [ ] 内容是人确认过的定稿，格式调整没有改动措辞
- [ ] 没有编造的经历或数字；保密细节已换掉
- [ ] 平台声明由人决定，Agent 没有代为承诺
- [ ] 推文按平台算法在上限内（`scripts/x_weight.py`）
- [ ] 编辑器里的标题、正文和定稿文件逐字一致，预览正常
- [ ] 停在发布按钮前，截图交给人
