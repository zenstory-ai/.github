# 出处与截图规范

每个结论都要给出读者能顺藤摸瓜核查的精确出处；配图必须忠实呈现源文件或真实页面。以下示例均为虚构。

---

## 1. 出处写法

| 引用对象 | 写法格式 | 示例 |
|---|---|---|
| 表格里的意见或数据 | 《文件名》「工作表名」第 N 行 + 单元格范围 | 《核对意见.xlsx》「服务」页第 14 行 B14:C14 |
| 表格里的公式 | 《文件名》「工作表名」单元格 = 公式原文，保存值 X | 《门店评分表 v3.xlsx》「陈列」页 H27 = AVERAGE(C27:C30)，保存值 3.5 |
| 文档条目或段落 | 《文件名》第 N 条（或第 N 节第 M 段） | 《店长试用笔记.docx》第 6 条 |
| 系统页面位置 | 环境 → 菜单路径 → 页面区块或题目名 | 测试环境 → 评分规则 → 效率 → 客流达标 |
| 代码或规则改动 | 业务白话描述（仅对内交接时可在括号附提交号，对外流转省掉提交号） | 投诉响应时长页面单位改为小时（提交 a1b2c3d） |

核对细则：
- **原话逐字照录**：原文里的笔误、多余空格、旧标点及意见人自填的分类标签一律原样照录；若整理后的跟踪表改顺了字句，正文以源文件原话为准并注明差异。
- **区分两套行号与三种数值**：源文件与删过空行的跟踪表行号不同时，写清行号属于哪份文件。区分工作簿**保存值**、按公式重新算出的**自算值**（标「自算」）以及为演示规则构造的**假设输入**（标「假设」；「假设」与「自算」可同时标出）。

---

## 2. 源文件与系统页面截图

### 源文件截图（呈现原貌，不重排冒充）
1. **先复制到临时目录再渲染**：优先用系统自带预览渲染原貌（如 macOS 用 `qlmanage -p -o <临时输出目录> <文件副本>` 把 xlsx/docx 渲染为网页，再用无头浏览器打开截图），绝不在源文件原目录直接生成散落文件。
2. **只加定位框，不改单元格文字**：可后加红框或箭头标出关键行列，图注必须写明「红框是后加的标注」。
3. **补齐画面看不见的信息**：预览图只显示保存值、不显示公式，白色字体或隐藏行在图里也看不见——公式原文与隐藏格内容必须在图注或紧邻正文里写明（如「第 18–20 行为隐藏行，图中不可见，内容见正文表」）。
4. **局部截取要交代省略与拼接**：宽表或长表只截相关行列并上下各留一两行上下文；跳过中间行或多段拼合时，图注写明「中间行已略去」或「两段截图拼接」。
5. **无法预览渲染时的兜底**：若环境确实无法渲染原件，可读取单元格原文排成表格再截，但图注必须如实标明「原文摘录（据源文件读取，非原件截图）」。

### 系统页面截图
- **只读操作**：截图时只浏览不提交，不点会改写数据的按钮。
- **切到对应页签与改后状态**：先点开正文所讲的具体步骤或页签再截；展示改动结果时截真实环境改后的页面，绝不用本地临时拼凑的假页面冒充改前或改后状态。
- **脱敏与内嵌**：逐张确认不含私有地址、凭据、未授权账号或其他客户名称；单文件 HTML 一律转成 `data:` URI 内嵌进 `<img src="data:image/...">`（大图可适度压缩但须保证 150% 放大投屏时字迹清晰），严禁写 `src="shot1.png"` 等外部相对路径以免转发丢图。

## 3. 图注正反例与交付前逐张核对

图注只写画面里真能看到的内容：文件或页面名、页签、行列/单元格、标注框指代的对象。

| 图注反例 | 问题 | 正确写法 |
|---|---|---|
| 「公式为三项相加」（图只截到前两项） | 图注超出了画面可见范围 | 换截完整公式，或写明「图中截出前两项，第三项为……」 |
| 「红框标出本次修改的两处」（实际共改五处） | 让人误以为只改了两处 | 「本次共改 5 处（第 2、3、6、9、11 处），红框标出其中两处」 |
| 「金额单位为万元」（C1 表头实为元） | 没看清表头写错单位 | 「C 列金额单位为元（见 C1 表头）」 |
| 被截的确认单或表格后来改了数字，截图没换 | 图文新旧打架 | 源稿每次改动后重新截图并核对关键数字 |
| 只写「旧版表第 1 页」（实际为连续网页渲染且文件清单无此简称） | 文件名对不上、页码失真 | 写全第一段文件表中的完整文件名，连续渲染写「文档开头」或具体行号 |
